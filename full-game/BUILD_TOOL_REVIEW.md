# Build-tool review — 26 September 2026, in progress

This review is separate from the [runtime dependency scan](DEPENDENCY_REVIEW.md) and [container scan](server/CONTAINER_DEPENDENCY_REVIEW.md). It is not yet complete. The bounded wrapper update to **8.14.5** passes full rebuild, JVM tests, lint and focused native acceptance. Broader build-library findings remain open; the **9.7.1 / AGP 9.3.3 / Kotlin 2.4.20** migration has only been evaluated in an isolated dependency probe. CI action updates are recorded below.

## Confirmed wrapper finding

The reviewed baseline selected Gradle **8.13**, with distribution SHA-256 `20f1b1176237254a6fc204d8434196fa11a4cfb387567519c61556e8710aed78`. The build selects AGP **8.13.2**, Kotlin/Compose compiler **2.2.21**, and JDK **17**. Its repositories are Google Maven, Maven Central and the Gradle Plugin Portal for plugins; project repositories are rejected. The dependency-verification file contains SHA-256 checksums and enables metadata verification, with no trusted-artifact bypass configured there.

| [GHSA-mqwm-5m85-gmcv / CVE-2026-22865](https://github.com/gradle/gradle/security/advisories/GHSA-mqwm-5m85-gmcv) | Fallback after repeated repository response failures has a similar resolution risk | 8.14.4 or 9.3.0+ |

Both advisories identify strict repository filtering or dependency verification as mitigations. The checked-in checksum verification provides that control for approved artifacts; this review does not infer compromise or waive a patched-wrapper update. The advisories concern dependency resolution during builds, not the installed game's room protocol.

## Broader build-only inventory, 26 September (in progress)

`tools/build-inventory.gradle` records Maven resolutions observed during the supplied tasks, including plugin marker/platform metadata with no binary artifact. It rejects unresolved graphs, fingerprints each external binary artifact, records task outcomes and identifies its scope as an observed build rather than a complete list of every potential tool. Gradle-distribution libraries, JDK/SDK/native binaries and CI JavaScript remain separate inputs. The advisory helper now accepts this explicit inventory kind while preserving the stricter runtime-artifact requirement. Six helper tests pass, including rejection of failed/unknown builds and unconfirmed resolutions.

The configuration-only probe resolves **155 distinct Maven module/version pairs** over nine resolutions. Its completed OSV query reports **47 distinct active advisory IDs across 12 affected module versions**. These are package matches, not reachability findings: build-classpath Netty 4.1.110.Final, Commons Compress 1.21, jose4j 0.9.5, Bouncy Castle 1.79, JDOM 2.0.6 and Kotlin Gradle plugin 2.2.21. The 155-module probe does not cover all compiler, processor, test and lint resolutions; full task execution is still required.

A separate Grype 0.119.0 directory scan of the hash-verified Gradle 8.14.5 distribution reports **16 matches: 1 Critical, 5 High, 10 Medium**. Its database is valid, hash-checked and built 25 September at 06:31:49 UTC. Findings include the embedded Bouncy Castle 1.84, Jackson 2.18.6, Plexus 3.5.1, JGit, Commons Lang, jsoup and EdDSA. The full distribution has a 317-file hash inventory. The scanner executable was rechecked against the previously checksum/attestation-verified official Windows ZIP. A successful scanner exit means it completed; it does not mean these findings passed a release gate. No finding has been suppressed.

The first full rebuild invocation omitted `TAMBOLA_PG_BIN`, so the actual-backup integration test failed its explicit prerequisite. The second invocation passed all 130 JVM tests, then exposed two collector defects: independent tasks could run before Android packaging finished, and selecting project artifacts without Android's artifact-type attribute was ambiguous. The collector now orders itself after all other scheduled tasks and filters for external Maven components before artifact selection. A Gradle 9.7.1 negative probe deliberately failed a task named after the collector on the command line; no inventory was emitted. Neither failed invocation is accepted as a complete build. Published alpha13 packages and their checksums remain unchanged.

The Kotlin finding [GHSA-r937-wjx7-w2jp / CVE-2026-53914](https://github.com/JetBrains/kotlin/commit/bf51df665b458fda7c3eaf436c4d88dc119d7ec6) concerns KAPT incremental-cache deserialization. Kotlin [2.4.20 is a stable release from 7 September](https://kotlinlang.org/docs/releases.html), so a beta is not required. Its [compatibility table](https://kotlinlang.org/docs/gradle-configure-project.html) lists Gradle through 9.7.0 and AGP through 9.3.1 as fully supported; later releases require additional validation. Android's [Kotlin/R8 compatibility guidance](https://developer.android.com/build/kotlin-support) must also be respected. Toolchain selection and any build-classpath constraints need their own provenance, compatibility and APK/service validation; installing a newer version alone is not acceptance.

Reproduce the configuration probe (quote the property argument in PowerShell):

```text
gradlew -I tools/build-inventory.gradle help buildDependencyInventory "-PbuildInventoryOutput=.test-workspace/build-config-inventory.json" --no-configuration-cache --no-build-cache
```

Use a fresh advisory output filename. For full coverage, replace `help` with the actual build/test tasks and run lint after both variants have compiled, to avoid the previously observed generated-stub lint race. Keep failed probes and dated scans as evidence; never equate configuration-only coverage or zero runtime matches with build-tool acceptance.
